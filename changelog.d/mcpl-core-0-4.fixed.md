- A host's request whose text holds a raw U+2028 or U+2029, such as a `send_message` call's `content`, is read whole and answered. On Node 24 the server split it at that character, logged the pieces as malformed lines and never answered. A line from the host now ends at `\n` alone, so a host that ends its lines with a bare `\r` is no longer read.
- U+2028 and U+2029 in anything this server sends are written as `\u2028` and `\u2029`, which JSON reads as the same characters, so a host whose reader ends a line at them, as Node 24's `readline` does, gets the message whole. Before, a message that carried one raw, such as a sender's display name as its author, was lost at such a host.
- When a connection's input fails, such as a TCP client's socket on a reset or stdio's stdin, only that connection ends. Over TCP the server goes on serving clients one at a time, as after a client that leaves, and on stdio it shuts down, as when stdin ends. Before, the error went uncaught and ended the process.
- These come with `@animalabs/mcpl-core` 0.4.0, which this server now requires (`^0.4.0`).
