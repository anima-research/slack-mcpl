- A partial rollback's answer now names, after the counts of each kind, each message and each uploaded file it couldn't delete, with its conversation. One whose delete failed in a way that can pass, or whose outcome is unknown, may remain: the answer says that no rollback tries it again, that `delete_message` can try a message among them again, and that no tool here deletes a file but whoever runs the host can, with Slack's `files.delete`, by its id. One Slack refused to delete in a way it will repeat is named apart, with the note that calling again won't change that. It used to give only the count of messages deleted, so the agent couldn't tell which were left.
- An answer the Slack client reads as a refusal but whose code isn't in Slack's form, such as an HTML page, is no longer taken as Slack refusing the call. A write's error says its outcome is unknown and how to check before trying again, unless the request that failed came before the write. Any other call's error says to try again, and that whoever runs the host should check its connection to Slack if it keeps failing. A user's name looked up that way isn't kept as the ID, and is asked again; channel registration's listing and name lookups wait and ask again; an acknowledgement's add is kept for removal, and its removal is tried again; and the DM check says to try again. An upload whose last step gets such an answer keeps its comment for a rollback's note.
