- **Tool clients:** history/thread truncation notes are replaced by structured `pagination`; check `scanComplete`/`stopReason` and repeat the original query with `nextCursor` as `cursor` to continue. Numeric limits now require bounded integers, and unknown arguments refuse, naming the arguments the tool takes and any they look like a slip for, a required one included. The default `maxBytes` of 64 KiB can end a default read before its match count, with `byte_limit` and a cursor; a call that can't return even its first message fails, naming the `maxBytes` that fits it. A `fetch_history` or `fetch_thread` that fails once it runs says "No messages were returned": its own failures, and its refusals of its arguments, open with it, and so does the explanation that follows a Slack error's text; a failure nothing explains is followed by it. The host's refusals every tool shares, such as a feature set it hasn't enabled, keep their own words. Existing tool names and default match counts are unchanged. Legacy writable semantics remain unchanged; explicit policy additionally requires applicable write pins and metadata read/effect grants. Internal backscroll now has a successful-page ceiling in both modes and, with an explicit policy, rejects repeated or non-string pagination cursors (without one, a repeated cursor runs to the ceiling unless the message limit stops it first); backscroll also has a separate 32 KiB frame budget with placeholders and older-prefix summaries (see the backscroll Changed entry). These bounds require no host upgrade or new OAuth scopes.

- **Embedded callers of `fetchSlackHistory`:** the exported helper defaults to
  at most 100 successful Slack pages per invocation. Pass `maxPages` (an integer
  from 1 to 10000) to override it, and handle `truncated` with optional
  `stopReason: 'page_limit' | 'message_limit'` on bounded results. Complete
  results retain the existing message payloads; no OAuth or host upgrade is
  required.
