- **Tool clients:** history/thread truncation notes are replaced by structured `pagination`; check `scanComplete`/`stopReason` and repeat the original query with `nextCursor` as `cursor` to continue. Numeric limits now require bounded integers, and unknown arguments refuse, naming the arguments the tool takes and any they look like a slip for, a required one included. The default `maxBytes` of 64 KiB can end a default read before its match count, with `byte_limit` and a cursor; a call that can't return even its first message fails, naming the `maxBytes` that fits it. A `fetch_history` or `fetch_thread` that fails once it runs says "No messages were returned": its own failures, and its refusals of its arguments, open with it, and so does the explanation that follows a Slack error's text; a failure nothing explains is followed by it. The host's refusals every tool shares, such as a feature set it hasn't enabled, keep their own words. Existing tool names, default match counts, internal backscroll and `list_channels.writable` policy semantics are unchanged; no host upgrade or new OAuth scopes are required.
