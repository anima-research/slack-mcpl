- A tool call or `channels/publish` that Slack refuses now says what Slack's answer means. The error used to be the Slack client's bare text, such as "An API error occurred: channel_not_found". That text still comes first. After it comes what didn't happen (nothing was posted, edited, deleted or read), the value the call was given, and what to do next: the tool that shows real ids (`list_channels`, `fetch_history`, `fetch_thread`, `find_user`), the tool that fits a conversation's threading rule (`reply_message` where only thread replies are taken, `send_message` where threads aren't), or a plain statement that calling again won't help and who can change it: whoever runs the host, for a missing scope or a bot token Slack no longer accepts, or the workspace's admins, for its settings. When Slack itself fails (`internal_error`, `fatal_error`, `service_unavailable`), a read says to try again, and a write says its outcome is unknown and how to check before trying again, so a message isn't posted twice. Other codes, and errors that aren't Slack's refusals, pass through unchanged unless another entry here explains them.
