- TCP reconnects keep one Slack forwarding callback and reset peer-owned channel, routing, and backscroll state. Pending work from an old connection cannot alter the next peer's context; subscriptions and rollback checkpoints remain intact (#4).
- Messages in one conversation are delivered one at a time, in order, so backscroll comes once, with the first message the host takes from it. A message looks up its conversation's backscroll and name at most once each. Each lookup gives up after five seconds, says so on stderr, and delivery continues without its result. Other conversations remain independent (#4).
- A TCP peer whose handshake fails no longer ends the process: the server closes that connection and waits for the next client. An addressed message dropped because there is no peer, its peer left, or `slack.messaging` isn't active before delivery is logged on stderr. When acknowledgment reactions are configured, the server requests them as addressed messages enter the queue. A dropped or refused message releases its reaction. Send-failure logs name the message and conversation (#4).
- Thread routing advances only once the host takes a message. A message's location header names its conversation when that differs from the last one the peer was sent a message from or the bot posted in. A message the host refuses or never receives, or whose header couldn't name its conversation, leaves the next message to name its own. Acceptance records the current peer's delivery context even if its messaging grant changed during the send (#4).
- A first message the host refuses, or that never reaches it, no longer uses up the conversation's first interaction: the conversation's next message is still its first, bringing backscroll if it's addressed, and a mention subscribes a conversation only together with the note saying so. Once the agent calls `unsubscribe_channel` for a conversation, a mention doesn't subscribe it again for the rest of the process, including before its first delivery, while the host's answer is pending, and across reconnects (#4).
