- This server's own refusals and notes now say what didn't happen, the value they're about, and what to do next, or that calling again won't help and who can change that. Several used to state a bare fact, such as `channelId is required`, `Unknown tool: x`, `No users matched.` or `fetch failed: 404 Not Found`. The new texts cover the write allow-list and the DM switch, a tool whose feature set the host hasn't enabled, a capability the host hasn't granted, an argument that's missing or isn't a string, an unknown tool (whose error lists the tools on offer), `find_user` with no match, the notes `fetch_history` and `fetch_thread` add when their limit leaves messages out, `fetch_attachment`'s failures, and the refusals of `channels/open` and `channels/publish`.
- The agent's texts no longer name `SLACK_SEND_CHANNELS` or `SLACK_DISABLE_DMS`, which an agent can't change. They name the conversations the bot may write to, and say that whoever runs the host decides. The startup log still says where the bot may write and whether DMs are on.
- `fetch_attachment` no longer answers with Node's bare `fetch failed` when a download fails on the way, or `Invalid URL` for a url it can't parse. A timeout, a rate limit or a server error from the file server says to try again; any other refusal says to pass the url exactly as the message gives it. A url that carries a user name or password is refused before anything is fetched, and a file name the url can't decode is kept as given rather than failing with `URI malformed`. A bot token holding a character a request header can't carry, such as a line break, is refused without being quoted; Node's own refusal quoted the whole token to the agent.
- With DMs off, a conversation Slack won't confirm as a channel is refused with what can change that: another conversation when Slack doesn't know it, and whoever runs the host when the Slack app lacks a scope, named when Slack names it, or its token is refused.
- An acknowledgement reaction whose removal Slack fails on, such as with `internal_error`, is tried again, as one that was rate-limited, got an HTTP error or failed in transit already was.
- `refresh_channels` without the host's `channels.register` grant is now an error, and asks nothing of Slack. It used to answer as a success whose note said nothing was announced, so an agent could take its conversations as registered. On a plain MCP connection, which has no host to register conversations with, `tools/list` no longer offers it, and a call is refused the same way. Its description now says it registers the conversations the bot is in, where it said every conversation the bot can see: public channels the bot hasn't joined were never registered.
- "Capability denied: <capability>" keeps its code (-32002), its `data` and its opening words, and gains a sentence: the request didn't run, and calling again won't change that until the host grants the capability.
