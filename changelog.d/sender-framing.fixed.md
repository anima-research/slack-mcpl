- A sender's words could take the shape of the server's own framing. A message with a line break, in any of its forms, could start a line that reads as a delivery line, a backscroll line, the end of `<backscroll>`, a `<system>` note or an attachment note, and a person's display name, a bot's name or a file's name went in as it was. Now:
  - each line break in a message's text, in the delivery line and in backscroll, starts a new line indented by two spaces, so a sender's text never starts a line at the left margin;
  - in a message's text, a `<` that opens one of the server's own tags (`<system>`, `</system>`, `<backscroll`, `</backscroll>`, in any case, with spaces, controls, marks or invisible characters inside, or with an `=` or a quote straight after the name) reads `&lt;`; other tags, such as `<b>` or `List<System.String>`, read as written;
  - a name the server shows (a person's display name, as an author or in a mention, a channel mention's label, a bot's name, a file's name, a conversation's or the workspace's name in a message's header) is shown as it is only when it holds letters, marks and numbers in any script, `_`, `.` and `-`, with single spaces between words, and no invisible character. Any other is shown as a JSON string, which `JSON.parse` gives back, with `<`, `>`, controls, line separators, the braille blank U+2800, spaces other than U+0020 and, outside an emoji, invisible characters escaped; so a name such as `O'Brien` is now shown quoted, and a mention reads `@"O'Brien" (uid:U123)`, in delivered messages, backscroll, and `fetch_history`'s and `fetch_thread`'s rows;
  - a message's text on one line, with none of the server's tags and no mention of a name that isn't plain, reads as before;
  - an attachment note shows a file's MIME type as it is when it has a MIME type's shape, parameters such as `charset=utf-8` included, and quoted otherwise. It shows an `http:` or `https:` link as the URL parser writes it, so a link holding a space reads with `%20`, and `fetch_attachment` takes such a link on `files.slack.com` as given; a link in any other scheme is quoted;
  - a backscroll line names its attachments before the message's text: `[… id=…] Ann [attachments: plan.pdf]: text`;
  - in every tool result written as JSON, a `<` that opens one of the server's own tags is written `\u003c`, and a U+0085, U+2028 or U+2029 its `\u` escape, so the server's tags in a message's text, a person's name or a channel's topic don't read as its own; parsed, each value is what it would be without these escapes;
  - in `fetch_history`'s and `fetch_thread`'s rows, an attachment's file name, MIME type and link follow the attachment note's rules;
  - a DM's label shows its person's name, and a group DM's label the group's name, by the name rule, as it's registered and as a write's `to` and `refresh_channels`' `added` give it; a conversation the host already holds keeps the label it was first announced with, while a write's `to` gives the new one;
  - `fetch_attachment`'s result for an image names the file and its type by the same rules;
  - other values in tool results are as they were, but that a read near its `maxBytes` can return fewer messages, since a row's escapes make it longer, and one whose first row no longer fits is refused as too big.
