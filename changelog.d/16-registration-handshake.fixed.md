- For `channels/register`, cache a descriptor only when the host's itemized answer accepts it (`accepted: true`), so `refresh_channels` can recover a refused, unanswered or timed-out registration. A descriptor the host refuses (`accepted: false`) is dropped even if an earlier answer accepted it, and closed if it was open. An omitted or malformed entry counts as unanswered and leaves its descriptor as it was. Each applied answer is logged once if it refuses or leaves out any channel, naming each with the host's reason where it gave one. An answer without itemized results is logged as accepting nothing. (#7)
- Discard a registration's listing, and the host's answer to its `channels/register`, once a re-grant, a revoke of `channels.register` or a disconnect has made the registration stale. `refresh_channels` doesn't list while the latest registration can still register and is still in flight, including its Slack listing and the host's answer, so this server applies that answer before a refresh lists. A refresh whose host connection has closed announces nothing. (#8)
- `channels/open` with a non-empty `channelId` or any address field opens the channel it names, or fails with "No matching channel found": the channel `channelId` names, or else, for type `slack`, the one `address.channelId` names. Only a request naming nothing falls back to the first registered channel of its type.
- Refuse `state/rollback`, with `success: false` and a reason, while `slack.messaging` isn't active on the asking connection: before its initial policy, or when its grant doesn't cover that feature set. This includes a TCP client that reconnects with an earlier checkpoint and a later policy that withdraws the feature set on the same connection. (#8)
